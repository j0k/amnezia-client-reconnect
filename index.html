🔍 What differs from the official client

  1. 🔁 Auto-reconnect watchdog — pings a host list → automatic reconnect configuration (interval, all/any mode, random order, status, Check now).
  2. 🧪 Test button under every host (resolved IP, packet loss, RTT).
  3. ⏱️ Stuck-reconnect recovery — abort → pause → retry (timeout / pause in seconds).
  4. 🏠 Home-screen indicators — auto-reconnect / direct proxy / logs.
  5. 📝 Event log — txt with timestamps, 4 checkbox categories.
  6. 🧩 Live app split-tunneling — no reconnect, page editable while the VPN is up.
  7. 🔀 Two local proxies — Direct (bypasses the VPN) + VPN (through the tunnel); each with bind address, port, optional login/password, IP allowlist, log; types SOCKS5 / HTTP / HTTPS (TLS) with an auto-generated certificate and export.
  8. 🟢 Tray — state-coloured icon (green / grey / red) that is visible on a light taskbar, tooltip with the state.
  9. 🎞 Process Recorder — timeline of processes (NEW / EXITED with run time, expand, full path, time slider).

✨ Features

🔁 Auto-reconnect watchdog

Pings a host list every N minutes through the tunnel and reconnects when they stop answering. All/any mode, random order, per-host Test, stuck-connection recovery (timeout → pause → retry), timestamped event log. Born from nightly internet drops the client never noticed.

📖 Setup & which hosts to ping: EN / RU

🔀 Two local proxies

Direct — bypasses the VPN with your real IP (e.g. matchtv.ru from Russia; “two browser windows, two IPs”). VPN — through the tunnel, so another PC on your LAN can use the VPN exit. SOCKS5 / HTTP / HTTPS (TLS), bind address, login/password, IP allowlist, log. One-click Launch of Chrome, Edge, Firefox or Yandex Browser through the Direct proxy, with the exact command line to copy.

🏗 Architecture with code links: EN / RU · 🔐 Certificates: EN / RU

🧩 Live app split-tunneling

Add or remove apps while connected — no reconnect. Reuses the existing service IPC; Windows driver is exclude-only.

🎞 Process Recorder

Timeline of running processes: NEW / EXITED with run time, start time, full path, scrub back in time, interval down to 0.5 s.

🏠 Home-screen indicators

“Auto-reconnect enabled”, “Direct proxy enabled (address)”, “VPN proxy enabled (LAN address)” and “Logs” right under the connect button.

🔀 VPN proxy — share your VPN exit with another PC or phone

The second local proxy (Settings → Local proxies → VPN proxy — through the tunnel) listens on your LAN and pushes everything it receives into the VPN tunnel, so another computer, a phone or a TV on the same network exits through your VPN server without installing anything.

  1. Turn it on, set Bind address to 0.0.0.0 (all interfaces) — the home-screen indicator then shows the address to use, e.g. http://192.168.1.10:8900.
  2. Recommended type: HTTP (CONNECT). It is the one every client understands: Windows Settings → Network → Proxy, Android/iOS Wi-Fi proxy settings, browsers, curl. SOCKS5 works only in apps that support it explicitly, and the HTTPS (TLS) type needs the self-signed certificate imported on every client and is not accepted by Windows system proxy settings at all. Inside your own LAN the extra TLS layer buys little — use HTTP unless the network itself is untrusted.
  3. Restrict who may connect: Allowed client IPs (e.g. 192.168.1.23, 192.168.1.24) and/or a login/password. An unlisted IP is dropped before a single byte is exchanged.?
  4. On the other device: proxy host = your LAN IP, port = 8900. Check: curl -x http://192.168.1.10:8900 https://api.ipify.org must print the VPN server's IP.
  5. Switch on Log requested hosts to see who asked for what: [time] NEW 192.168.1.23 -> chat.qwen.ai:443.

The Windows firewall must allow inbound TCP 8900 for amnezia-direct-proxy-vpn.exe (Windows asks on first start). Details and code: docs/proxy/ARCHITECTURE.md.
