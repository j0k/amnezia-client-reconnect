# 🔐 Сертификаты HTTPS-прокси — инструкция

Здесь описан TLS-сертификат, который использует тип прокси **HTTPS (TLS-encrypted)** в
Settings → Connection → *Local proxies*: зачем он нужен, как генерируется, как установить
(«доверить») его на устройствах и как подключаться через прокси.

> 🇬🇧 English version: [README_certs.md](./README_certs.md)

---

## 🧭 1. Зачем нужен сертификат

У прокси три типа:

| Тип | Канал клиент → прокси | Для чего |
|---|---|---|
| SOCKS5 | открытый | локально, универсальный |
| HTTP (CONNECT) | открытый | локально, браузеры |
| **HTTPS (TLS)** | 🔒 **зашифрован** | прокси наружу в сеть (другой ПК, Wi‑Fi, VPN-прокси) |

С **HTTPS** соединение *от браузера до самого прокси* шифруется TLS — никто в сети не
увидит, какие хосты ты открываешь, и не перехватит логин/пароль от прокси. Внутри этого
шифрованного канала — тот же HTTP CONNECT.

Для TLS прокси нужны **сертификат + приватный ключ**. Прокси личный, поэтому используется
**самоподписанный** сертификат — бесплатно, мгновенно, без удостоверяющих центров. Единственный
дополнительный шаг — **один раз доверить** его на каждом клиентском устройстве (браузеры
отказываются работать с HTTPS-прокси, чей сертификат не доверен).

---

## ⚙️ 2. Автоматическая генерация (основной путь)

Обычно руками ничего генерировать не надо:

1. Открой **Settings → Connection → Local proxies**.
2. В блоке нужного прокси (Direct или VPN) выбери **HTTPS (TLS-encrypted)**.
3. **Включи** прокси.

При первом запуске helper (`amnezia-direct-proxy.exe`) сам создаёт пару:

```
%APPDATA%\AmneziaVPN…\proxy-direct.crt   ← сертификат (PEM)
%APPDATA%\AmneziaVPN…\proxy-direct.key   ← приватный ключ (PEM)  🔑 никому не отдавать!
%APPDATA%\AmneziaVPN…\proxy-vpn.crt / .key   ← то же для VPN-прокси
```

Свойства сертификата:

- 🧾 Самоподписанный, **RSA‑2048**, подпись SHA‑256
- 🏷️ `CN = amnezia-proxy`, `O = AmneziaVPN reconnect fork`
- 🌐 **SAN** (для каких имён действителен): `localhost`, `127.0.0.1`, плюс **bind / LAN-IP**
  прокси (чтобы подходил и удалённым клиентам)
- 📅 Срок действия — **10 лет**
- 🎯 Назначение: `serverAuth`, `CA:FALSE`

В приложении адрес показывается как `https://<host>:<port>`.

## 📤 3. Экспорт сертификата

Клиентским устройствам нужен **сертификат** (публичная часть) — и **никогда** `.key`.

В блоке прокси при выбранном HTTPS нажми **🧾 TLS certificate**. Приложение скопирует
сертификат на рабочий стол:

```
%USERPROFILE%\Desktop\amnezia-proxy-direct.cer
%USERPROFILE%\Desktop\amnezia-proxy-vpn.cer
```

(`.cer` — это PEM-сертификат; его принимают Windows, macOS, Linux и браузеры.)
Файл можно передать на другое устройство любым способом — **секретов в нём нет**.

> ℹ️ Кнопка сработает только после того, как HTTPS-прокси был запущен хотя бы раз
> (именно тогда файл создаётся).

## ✅ 4. Установка («доверие») сертификата на клиенте

Делается **один раз на каждом устройстве**, которое будет ходить через прокси.

### 🪟 Windows

**Через интерфейс:** двойной клик по `.cer` → **Установить сертификат…** → *Текущий
пользователь* (или *Локальный компьютер* для всех) → **Поместить все сертификаты в следующее
хранилище** → *Обзор* → **Доверенные корневые центры сертификации** → Готово → подтвердить
предупреждение.

**Командная строка (от администратора):**
```powershell
certutil -addstore Root "%USERPROFILE%\Desktop\amnezia-proxy-vpn.cer"
```
Только для текущего пользователя, без админа:
```powershell
certutil -user -addstore Root "%USERPROFILE%\Desktop\amnezia-proxy-vpn.cer"
```

### 🍎 macOS
```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain amnezia-proxy-vpn.cer
```
Или: открой файл в **Связке ключей** → добавь в *Система* → двойной клик → *Доверие* →
**Всегда доверять**.

### 🐧 Linux (Debian/Ubuntu)
```bash
sudo cp amnezia-proxy-vpn.cer /usr/local/share/ca-certificates/amnezia-proxy.crt
sudo update-ca-certificates
```
(Fedora/RHEL: `/etc/pki/ca-trust/source/anchors/` + `sudo update-ca-trust`.)

### 🦊 Firefox (любая ОС)
У Firefox **своё** хранилище. Настройки → Приватность и защита → *Сертификаты* →
**Просмотр сертификатов** → *Центры сертификации* → **Импортировать…** → выбрать `.cer` →
поставить галку **«Доверять при идентификации веб-сайтов»**.

### 📱 Android / iOS
Импортируй `.cer` как пользовательский CA-сертификат (Android: Настройки → Безопасность →
*Установить сертификат*; iOS: открыть файл → установить профиль → включить полное доверие
в *Настройки доверия сертификатов*). Затем укажи прокси в настройках Wi‑Fi или приложении.

## 🌐 5. Подключение через HTTPS-прокси

Формат адреса: **`https://HOST:PORT`** — например `https://192.168.1.5:8900`.

### Chrome / Edge / Chromium
```powershell
chrome.exe --proxy-server=https://192.168.1.5:8900 --user-data-dir=%TEMP%\proxy-profile
```
(Кнопка **«Launch browser via this proxy»** в приложении делает ровно это для Direct-прокси.)

### Firefox
Настройки → Параметры сети → **Ручная настройка прокси** → заполни **HTTPS-прокси** хостом и
портом (HTTP-прокси оставь пустым, если не нужен обычный HTTP через него).

### Системный прокси Windows
⚠️ Встроенный системный прокси Windows (WinHTTP / Свойства обозревателя) **не поддерживает**
прокси со схемой HTTPS. Для HTTPS-прокси используй флаги браузера выше, PAC-файл или
расширение вроде SwitchyOmega. (Обычные HTTP / SOCKS5 прокси с системными настройками работают.)

### С логином / паролем 🔑
Если включено **Require login / password**, браузер сам спросит учётные данные
(HTTP `407 Proxy Authentication Required`). Для curl:
```bash
curl --proxy https://192.168.1.5:8900 --proxy-user USER:PASS https://api.ipify.org
```

### Быстрая проверка через curl 🧪
Пока сертификат не доверен, для теста отключи проверку:
```bash
curl --proxy https://127.0.0.1:8900 --proxy-insecure https://api.ipify.org
```
После установки доверия та же команда работает **без** `--proxy-insecure`.

## 🔄 6. Перегенерация сертификата

Перегенерируй, когда:
- 🌐 **сменился bind / LAN-IP** прокси → SAN больше не совпадает → браузеры ругаются;
- 🔑 есть подозрение, что приватный ключ утёк;
- 📅 истёк срок (через 10 лет 🙂).

Шаги:
1. **Выключи** HTTPS-прокси.
2. Удали пару:
   ```powershell
   Remove-Item "$env:APPDATA\AmneziaVPN*\proxy-vpn.crt", "$env:APPDATA\AmneziaVPN*\proxy-vpn.key"
   ```
   (или `proxy-direct.*` для Direct-прокси)
3. **Включи** прокси → создастся новая пара.
4. **Заново экспортируй** и **заново доверь** на всех клиентах (старый теперь недействителен).

## 🛠️ 7. Ручная генерация через OpenSSL (продвинутый вариант)

Если нужно своё имя или дополнительные SAN (DNS-имя, несколько IP) — создай пару сам и
положи вместо автосгенерированных файлов:

```bash
openssl req -x509 -newkey rsa:2048 -sha256 -nodes -days 3650 \
  -keyout proxy-vpn.key -out proxy-vpn.crt \
  -subj "/CN=amnezia-proxy/O=AmneziaVPN reconnect fork" \
  -addext "subjectAltName=DNS:localhost,DNS:myproxy.home,IP:127.0.0.1,IP:192.168.1.5" \
  -addext "extendedKeyUsage=serverAuth" \
  -addext "basicConstraints=CA:FALSE"
```

Затем скопируй `proxy-vpn.crt` / `proxy-vpn.key` в папку `%APPDATA%\AmneziaVPN…`
(с заменой) и перезапусти прокси. Helper использует те PEM-файлы, что там лежат.

## 🧯 8. Решение проблем

| Симптом | Причина / решение |
|---|---|
| Браузер: сбой подключения к прокси / «сертификат не доверен» | Серт не доверен на этом устройстве → §4. Firefox требует **свой** импорт. |
| `curl: (60) SSL certificate problem` | То же — доверь серт или добавь `--proxy-insecure` для теста. |
| Работает на 127.0.0.1, но не с другого ПК | В SAN нет этого IP → перегенерируй (§6) после установки bind-адреса / LAN-IP. |
| `curl: (7) Failed to connect` | Прокси не запущен / не тот порт / firewall. Проверь, что прокси **включён** и порт открыт. |
| Обычный `http://` к HTTPS-порту не работает | Так и должно быть — порт говорит **только TLS**. Используй `https://`. |
| Системный прокси Windows игнорирует | Системный прокси не умеет HTTPS-схему → флаги браузера / PAC. |
| «Start the HTTPS proxy once to generate the certificate» | Сначала включи HTTPS-прокси, потом экспортируй. |

## 🛡️ 9. Про безопасность

- 🔑 **Никогда не передавай `.key`.** Клиентам уходит только `.cer`.
- 🧩 Доверенный самоподписанный корень может подписать *любое* имя — ставь его только на
  **свои** устройства.
- 🔒 Для прокси, открытого в сеть, сочетай **HTTPS** + **логин/пароль** +
  **Allowed client IPs**. TLS прячет трафик; авторизация и allowlist не пускают чужих.
- 🧱 Windows Firewall при первом входящем подключении спросит разрешение — разрешай только для
  доверенной сети (Частная).
